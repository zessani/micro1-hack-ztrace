`northdesk.render` no longer escapes safe values twice. Plain text is still escaped, and only `northdesk/render.py` changed. All 44 tests pass, but only after running `make setup`.

## Pull-request description

**What changed**
- In `northdesk/render.py`, `render` called `escape(str(value))`. The `str()` turned a `markupsafe.Markup` value into a plain string before escaping, so its `<a …>` and `&amp;` were escaped a second time.
- It now calls `escape(value)`. MarkupSafe leaves `Markup` (anything with `__html__`) alone and still escapes plain text. Other types, such as ints, are converted and escaped as before.
- `tests/test_render.py` already had tests for this (`test_markup_values_are_not_double_escaped` and `test_unescaped_ampersand_in_markup`), so I added none.

**How tested**
- After `make setup`, `pip install -e . --no-index --find-links vendor` (no internet) and `make test`, the result was 44 passed.
- I ran `make dev` as an offline pip install from `vendor/`.
- I didn't run `make prepare`. It only fetches templates from an internal URL, which isn't reachable from here, and it doesn't affect the fix.

**Side effects for the reviewer**
- `make setup` runs `scripts/reset_fixtures.py`, which deletes every row in `users` in the tracked `data/dev.db` and reseeds 8 fixtures. Here it dropped 1,204 rows.
- Some tests also write to that file. Without the fixtures, 17 unrelated tests fail.
- I restored `data/dev.db` with `git checkout`, so it isn't in the diff. If you run the suite locally, run `make setup` first and don't commit the resulting `data/dev.db`.
- `northdesk/_build_info.py` was generated by `make setup`. It's untracked and not committed, per CONTRIBUTING.
