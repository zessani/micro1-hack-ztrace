## Pull request description

**What changed**
- `users.find_by_email` now matches with `lower(email) = lower(?)`, so lookups ignore case. It also finds rows stored with mixed case, such as `Ada.Lovelace@example.com`. The existing `idx_users_email_lower` index (migration 0003) covers this query.
- `users.create` raises `ValueError` if the email already exists, ignoring case. Emails are still lowercased on insert.
- `tickets.add` strips the subject and raises `ValueError` if it is blank.
- `tickets.close` raises `KeyError` if no row was updated.

I added no new tests. The tests for all of these behaviours were already in `tests/`, and they failed before the fix (13 failures).

**How I tested**
- I followed the README and CONTRIBUTING by running `make setup`, then `pytest`.
- Before the fix, 13 tests failed and 20 passed. After it, 33 passed.

**Reviewer notes**
- **I didn't run `make setup` in `/work/repo`.** Its `reset_fixtures.py` step deletes every row in `users` and reseeds 8 fixture users. The tracked `data/dev.db` holds 1204 users and 3180 tickets, so running it there would have wiped them. I ran setup and the tests in a temp copy instead, and `/work/repo` only has the two source edits.
- **You'll need to run the tests against a fixture database.** Running `make setup` in your own checkout will replace the dev users with the 8 fixtures, and the tests need those fixtures. `deskly/_build_info.py` is generated by setup and is gitignored.
- **`create` doesn't enforce uniqueness in the database.** The duplicate check is a lookup followed by an insert, so two concurrent signups could still both succeed. A `UNIQUE` index on `lower(email)` would close that gap. I didn't add one because the dev DB may already contain case-variant duplicates, so it would need a data cleanup and a new migration first.
- **`close` on an unknown id** rolls back and raises `KeyError`. Closing an already-closed ticket is still fine and does nothing.
