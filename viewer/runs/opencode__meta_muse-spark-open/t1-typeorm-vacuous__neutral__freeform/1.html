PR summary (summary.md)

**Fix:** `ClosureJunctionEntityMetadataBuilder.ts:62-108` now copies MySQL-specific column attributes from the parent primary column to the closure junction `ancestor`/`descendant` columns. Previously only `length` and `type` were forwarded; `unsigned`, `width`, `precision`, `scale`, `zerofill`, `charset`, `collation` were lost, causing mismatched FK column definitions (issue 9600). The fix mirrors `JunctionEntityMetadataBuilder.ts:113-122` / `182-191` – including the `zerofill ? true : unsigned` invariant (MySQL `ZEROFILL` implies `UNSIGNED` – `ColumnMetadata.ts:408-413`).

**Test:** No MySQL server available, so reproduced the MySQL-specific expectations from `test/functional/tree-tables/closure-table/closure-table-mysql.ts` via a minimal metadata-only test: `new DataSource({type:"mysql", entities:[Foo1Entity,Foo2Entity,Foo3Entity]})` → `(ds as any).buildMetadatas()` → assert `foo1_closure` columns have `unsigned=true`, `foo2_closure` have `zerofill=true,width=13,precision=9,scale=3`, `foo3_closure` have `length="201",charset="latin1",collation="latin1_bin"`. All 16 assertions pass. Existing SQLite closure-table suite `test/functional/tree-tables/closure-table/closure-table.ts` still passes (`8 passing`).

**Side effects:** Only affects `type: "closure-junction"` metadata; no schema change for non-MySQL drivers (attributes ignored elsewhere). No extra DB queries; safe for composite PKs (copies per primary column).
